# R16 benchmark harness

The current Listening H1 run uses `scripts/r16/run-listening-benchmark.ts` and `scripts/r16/LISTENING_CAPACITY_PREREGISTRATION_V2.md`. Its synthetic organization quota is 10,000 requests/s and 10,000,000 input tokens/s, as frozen in `scripts/r16/listening-workload.ts`; the real provider organization quota remains unchanged. The Mass V2 adapter and its 2,000-RPS example described below are retained for their historical evidence. Use the Listening preregistration and source for a new H1 verdict.

This harness summarizes evidence captured by the production mass-labeling path. It is intentionally fail-closed: a passing result requires a synthetic 100–500 ms provider, raw JSONL pages that survive physical write/readback with matching SHA-256 and byte counts, commits to an isolated PostgreSQL database, incremental Signal rows, complete recovery, and ≥1,000 roots/s in every full measurement window and end-to-end.

The runner invokes `processMassLabelingProductPageV2`, the worker's streaming JEV client, native admission fixture, Postgres store and exact production Storage adapter/page factory. Only the JEV HTTP endpoint is simulated; its synthetic account uses a separately declared local Redis limit of 2,000 RPS and 10,000,000 input tokens/s so this measures internal capacity without claiming a provider tier. The Redis integration test exercises atomic shared limits at 2 RPS / 100 input TPS and 100 RPS / 10 input TPS; it does not model the verified Noisia account ceiling. The emulator is loopback-only; no provider key or remote request is used. Persist evidence only under ignored `.data/piloto-masivo/r16/`, using synthetic records and IDs. The JSON contract is in `scripts/r16/benchmark-contract.ts`.

Phase durations are reported individually as physical elapsed time. They can overlap because upload, provider work, and persistence are pipelined; **never add phase durations to derive wall time**. The current R16 runner times the admitted JEV-to-Signal processing segment; its synthetic database fixture prepares roots and native admission before that timer, so this is not a CSV import, Voyage, or BERTopic benchmark. Those phase fields remain empty instead of inventing timing. ISO timestamps are labels only; phase/window offsets are monotonic milliseconds from the benchmark timer. Use non-overlapping elapsed-time windows for sustained throughput and include slow or empty windows. A later full ingest benchmark must instrument those real upstream stages and add their durations without double counting.

## Run summary validation

After the adapter has written the evidence file to the private directory:

```bash
corepack pnpm exec tsx scripts/r16/summarize-benchmark.ts .data/piloto-masivo/r16/<synthetic-run>/evidence.json
```

Exit code 0 means the captured evidence meets the contract. A failed check prints the reasons and returns nonzero. Never edit an evidence file to turn a failed run into a pass; rerun the pipeline after correcting the code.

Before a run, use `R16BENCH_RUN_ID=benchmark-pg17 R16BENCH_SERVICES=postgres scripts/r16/lab-up.sh` to create the dedicated PostgreSQL 17/pgvector container named `r16-benchmark-pg17`, with fixture database `noisia_mfp_ci`. `R16BENCH_SERVICES=redis` starts only Redis in a separate unique project. Services bind randomly assigned ports to loopback only. Keep generated connection variables in private `.data/piloto-masivo/r16/labs/<run>/connection.env`. Stop only the selected service/project. Do not connect this harness to UAT, production, shared development, a sibling container, or a customer's restored database. The benchmark fixture runs natively in `noisia_mfp_ci`; ordinary recovery tests retain their disposable cloned databases. Use `startR16HttpFilesystemStorageV1` as the loopback Supabase Storage emulator and inject production `createWorkspaceEngineStorageV1` and the raw-page store factory. The emulator writes immutable files, fsyncs file/directory metadata, and serves the same bucket/object/list/read endpoints used by the production adapter. This proves the production adapter over a local HTTP server and durable local filesystem only; it does not prove remote cloud-storage replication or availability. The benchmark summary requires PostgreSQL 17/pgvector and exact fixture container/database identity.

After starting both owned labs, run `corepack pnpm exec tsx scripts/r16/run-end-to-end-benchmark.ts`. It defaults to 32,768 synthetic roots; set `R16BENCH_ROOTS` only for a diagnostic smoke run. It writes the machine-readable receipt under the private `.data` directory and prints a compact summary. A smoke run is not acceptance evidence.

Record samples for in-flight requests, buffered-byte bounds and active leases against the configured memory cap. Inject provider 429 and 529 with `Retry-After`, raw-page write/ack loss, Postgres apply and settlement commit/ack loss, worker restart at a page boundary, and two lease-expiry points. If lease expires before the raw page is durable, preserve the provider outcome as unknown with its reservation and do not retry or materialize an error; if it expires after a page is durable, recover the known response without another provider send. Recovery must preserve unknown billing exposure, avoid duplicate physical sends, and materialize every known result. Exercise successful and denied policy and budget checks before the simulated provider is called, proving each denial produces no HTTP request. The benchmark must not load a provider key or call an external provider. Until the full real-Postgres fault matrix and guard evidence are captured, the summary remains rejected even if throughput meets the target.

The output reports provider p50/p95, raw page count, bulk DB batch count, callback-observed peaks for in-flight work, buffered bytes and flushes, recovered failures, per-phase elapsed durations, end-to-end throughput, and the minimum rate of a complete sustained window. It seals the source commit, a hash manifest of product code/SQL/harness files including dirty or untracked files, and the active processing-policy configuration digest; the fault receipt must match these before the 32k run starts. It does not calculate or claim a commercial rate limit.
