# Recorrido cliente administrador: contraste focal de permisos

9 septiembre 2026. Lectura local de runtime **070c94eee9759801f2586760475822eccbdd1d6d**, contrastada con el corte UAT **c8f05b9**. Los archivos de roles, guards, layout/páginas de marca, capabilities, selección y entrada de import/preparación citados no cambian entre esos commits. Se leyó AGENTS Studio y el Compass vigente desde el checkout focal original (`noisia-website/docs/product/PROMPT_LOOPING/COMPASS_SELF_SERVICE_2026-09-07.md`, ausente en el aislado).

**Conclusión:** el recorrido demostrado por el operador interno todavía no equivale a autoservicio para un cliente administrador. Esto confirma la deuda existente **NOI-19/NOI-20**, no un nuevo hallazgo ni una regresión de autorización. El cliente tiene APIs de lectura, edición acotada e import/preparación de texto, pero las pantallas de configuración están bajo Studio interno. Preparación semántica, embeddings, ejecución y selección en Signal permanecen bloqueadas. La renovación/admisión pagada añade la política pendiente **NOI-81**.

Alcance: cliente activo `user_type=client`, rol `client_admin` (incluye aliases brand_manager/client_owner), misma organización, workspace/marca activos y grant de marca no revocado `comment` o `admin`. Incluso con grant `admin`, su rol no se convierte en Noisia admin. No se creó usuario ni se probó login cliente, API remota, proveedor o UAT; las consecuencias siguientes son lectura del código, no QA con ese rol.

## Capability central y consecuencia práctica

`infrastructure/db/signal-workspace-capabilities.ts:23–39` parte con todo false. Para cliente admin de la misma organización concede view/edit/import según grant, pero no asigna execute/adopt. El grant de marca `admin` no altera esa decisión. Cambiar un guard de pantalla no habilitaría el resto del recorrido.

No todos estos bloqueos obligan a SQL/consola: hoy un operador interno puede hacer alta, Brand OS, ejecución y selección desde las pantallas existentes. El problema de autoservicio es que el cliente necesita ese intermediario cotidiano. Si además falta autoridad de gasto/proveedor, entra la política operativa NOI-81; no hay justificación para usar scripts o ampliar grants clandestinamente. Las capacidades API ya entregadas de import/texto no demuestran accesibilidad del producto para el cliente.

## Menor siguiente resultado productivo propuesto

Un corte **NOI-19 de administración de marca ya asignada, sin ampliar gasto**: hacer alcanzables los componentes existentes de Topics/Datos desde una entrada autenticada y scoped a esa marca, sin abrir todo Admin/Studio; mantener equipos, organizaciones, creación/movimiento de marcas y controles internos protegidos. Reusar can_edit_topics/can_import_mentions para el borrador y la carga/preparación de texto. Dar acceso visible a las acciones ya autorizadas requiere revisar el layout y los loaders de esas páginas, no sólo ocultar navegación.

Dentro del mismo objetivo, separar **seleccionar/quitar un Topic en Signal** del permiso de ejecutar modelos: autorización específica de edición de la marca en wrapper/store/guard SQL, conservando CAS, scope, membresías actuales, derechos y receipts. No modificar globalmente `can_execute_topics` o `signal_workspace_classification_actor_v1` para lograrlo. Esa separación permite al cliente decidir qué seguir usando resultados ya disponibles, sin conceder gasto ni aprobación semántica.

Brand OS/alta y autorización de análisis completo requieren la política acordada de NOI-19/81 antes de implementación: campos editables, organización y propiedad del presupuesto/original actor, límites y quién puede detener envíos. No prometo que el corte de acceso anterior cierre por sí solo el Compass. **NOI-20** debe registrar la prueba posterior con un cliente admin real de marca nueva y segunda carga, incluyendo un workspace ajeno denegado, borrador preservado y evidencia; hoy esa aceptación no está demostrada.

No se reabrieron gates PG/auth cerrados, no se cambió código y no hacen falta tickets duplicados: este mapa alimenta NOI-19, NOI-20 y NOI-81 existentes.
