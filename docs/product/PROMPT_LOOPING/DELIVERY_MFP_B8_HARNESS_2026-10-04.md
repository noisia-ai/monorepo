# Fase B · punto 8 — simplificación del harness y receipts

La base del corte evita guardar dos veces la respuesta cruda: `signal_labeling_calls` conserva clave privada, SHA-256 y tamaño; el worker recupera el objeto al reanudar y verifica su SHA antes de parsear. La migración forward-only `0255_signal_labeling_receipts_in_object_storage.sql` hace backfill del tamaño, valida referencias y elimina `raw_body`. También elimina `selection_complete`, que no tenía consumidores. No se modificaron migraciones anteriores.

Se retiró el formato de solicitud ordinal V4, que no seleccionaba el runtime vigente, junto con su parser, pruebas y modo de probe; siguen V1–V3 para reproducir identidades históricas usadas. `sample.mjs` deduplica por ID de proveedor, por lo que IDs distintos con el mismo texto se conservan y conflictos del mismo ID fallan explícitamente. La prueba de concurrencia que revoca política ahora exige una organización fixture desechable (`facets-lock-check-<sufijo>`). Los recorridos leen receipts por una función compartida del Worker y las comprobaciones de JEV consultan la clave de storage.

La auditoría menciona también una copia persistida de `request` fuera de Postgres. En `develop` no existe `request_storage_key` ni una escritura verificable de esa solicitud a object storage; por integridad de replay, este corte conserva `request`, `inputs` y `request_digest` en PG y limita la extracción a los receipts crudos que sí tienen clave y SHA demostrables. `jev-policy.ts` aún conserva su transición SQL de proveedor: la función producto disponible fija Anthropic y modifica tres acciones, mientras el harness debe cambiar sólo `mention_facets`; extraer esa autoridad en un método de producto específico sigue pendiente.

Validación local: `pnpm dev:corpus:check` (9/9), Query Engine (580/580), pruebas focales Worker (22/22) y Studio (8/8); typecheck de Query Engine, DB, Worker y Studio; `git diff --check`. Dependencias instaladas desde la caché offline del lockfile. Coste externo: USD 0; no hubo llamadas a proveedores. Modelo de implementación: **gpt-6-luna, esfuerzo high**.

La prueba PostgreSQL de aplicación/recuperación de 0255 queda pendiente: no se aplica en el runner hasta que Fase A libere y coordine SQL 0250–0251. La comprobación de bloqueo quedó protegida por fixture desechable; los demás recorridos de integración siguen usando su workspace dedicado de desarrollo MFP.
