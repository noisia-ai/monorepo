# R16 blind package tooling

The read-only native exporter binds explicitly supplied Listening generations and one completed Study execution to the exact workspace/actor. It writes only private `.data/piloto-masivo/r16/` files. The packager then creates blind auditor packets and a separately held custody key; neither tool edits labels, calls a provider, or runs either study. Use synthetic fixtures in tests. Do not run an export for a client corpus until the operator has approved it and the required native source evidence is available.

## Commands

```sh
pnpm exec tsx --tsconfig tsconfig.base.json --test scripts/r16/blind-package.test.ts scripts/r16/native-audit-export.test.ts
NOISIA_R16_NATIVE_AUDIT_EXPORT_APPROVED=1 pnpm exec tsx --tsconfig tsconfig.base.json scripts/r16/native-audit-export.ts \
  --workspace <workspace-uuid> --actor <authorized-user-uuid> \
  --before-generation <exact-generation-uuid> --after-generation <exact-generation-uuid> \
  --study-execution <completed-execution-uuid> \
  --out .data/piloto-masivo/r16/native-snapshot.json
pnpm exec tsx --tsconfig tsconfig.base.json scripts/r16/blind-package.ts build \
  --snapshot .data/piloto-masivo/r16/native-snapshot.json \
  --seed .data/piloto-masivo/r16/custody-seed.txt \
  --out .data/piloto-masivo/r16/blind-package \
  --key .data/piloto-masivo/r16/custody/answer-key.json
pnpm exec tsx --tsconfig tsconfig.base.json scripts/r16/blind-package.ts verify --package .data/piloto-masivo/r16/blind-package
```

The exporter requires an explicit `NOISIA_R16_NATIVE_AUDIT_EXPORT_APPROVED=1` environment value and `DATABASE_URL`; it prints no identifiers, text, URLs, or secrets. The command is an operator action and must not be run against a client corpus before separate approval. The custody seed must be at least 32 bytes, have no group/other permissions, and be created and retained privately by the custodian. The snapshot must also have no group/other permissions. The packet directory and custody key must be separate, new paths under `.data/piloto-masivo/r16/`; the builder refuses existing output/key paths and symlinked paths. A per-output exclusive lock and atomic hard-link publication make concurrent writers fail closed if a key already exists; there is no check-then-overwrite path. It uses mode `0700` for directories and `0600` for files, builds in a temporary sibling directory, then publishes the packet directory by atomic rename. If a process dies, inspect a leftover `.lock` and confirm no builder is running before removing it. Back up the custody key separately from the auditor packet. Do not send the manifest or answer key until the auditor has frozen results; do not share the seed.

Packet filenames and row order are deterministic from the custody seed but opaque: they do not encode study, stage, cohort, label, or stratum. Each packet has an opaque `packet_ref`; the manifest maps that ref to a generic filename and aggregate census counts so each shortfall is identifiable to the auditor without exposing the stage or semantic stratum. Visible stratum and axis coverage arrays are separately shuffled from the private custody-manifest order; only the separate custody manifest maps refs back to semantic stratum names. Axis subcoverage refs point to the single combined three-axis packet, but do not reveal which subquota a row belongs to. The manifest records source snapshot digest, measured stage cost/timing receipts, axis coverage shortfalls, and packet file hashes. Nearest-four sampling stays short when native rank and a unique prediction are unavailable; candidate keys and multi-label assignments remain separate in the private snapshot. The two-pass κ value, status, denominator, coverage, and recode count are excluded from the auditor packet and retained in the custody key; a generic required-evidence-missing state makes an incomplete build explicit. `SHA256SUMS` covers every packet and the manifest, excluding the separately held answer key. `verify` checks packet structure, manifest-to-packet digests and ref coverage, and all SHA256 entries. A build with any sample shortfall or missing κ evidence writes the census but exits with status 2; it cannot be presented as meeting the target sample/evidence requirements.

## Snapshot contract (`r16-blind-snapshot-v1`)

The native exporter writes one JSON object with:

- `exported_at`, and `source.export_contract` plus `source.export_digest` (SHA-256 hex of the immutable export/artifact manifest).
- `study_provenance.listening_before_digest` and `.listening_after_digest` (SHA-256 hex of each immutable configuration/map), `study_contract_version: "signal-study-v1"`, `methodology_template_version: "r16-v1"`, and the exact `methodology_template_digest` (`sha256:` prefix plus hex). These values bind the packet to the native versioned study contracts and keep before/after map provenance separate.
- `study_guidance`: exact subject context and option definitions for direction, target and use, plus the versioned layer diagnostics/questions/definitions. The auditor needs this context to code all three axes and the motive layer without seeing the model's answer.
- `layer_agreement`: nullable two-pass agreement receipt containing eligible count, each pass's observed count and artifact digest, paired denominator, coverage, observed/expected agreement, κ or `null`, estimation state/reason, action, and boundary-recode count. The validator checks counts, digests, coverage arithmetic, the κ formula, and status/value consistency against the native `signalStudyLayerStabilityV1` result. Numeric κ is valid only when both passes cover the full eligible census and the paired denominator equals it. Partial coverage requires `kappa: null` and `insufficient_data`, which makes package evidence incomplete. Full coverage with expected agreement `1` requires `kappa: null`, `not_estimable`, and reason `expected_agreement_one`; this is a complete observed receipt, not fabricated κ or a coverage shortfall. Missing and unmeasured receipts stay explicit. A fully measured κ below 0.8 is retained and reported without blocking the package. The receipt is retained with the custody key, never in the blind packet or public manifest.
- `receipts.status`, nullable `total_cost_usd`/`total_elapsed_ms`, and a nonempty `receipts.stages[]` with unique actual stage names. Complete receipts require actual stage cost and elapsed values whose sums match the totals (cost within USD 0.000001, time within 1 ms). An absent measure stays `null`, marks the package evidence incomplete, and is never converted to zero.
- `listening[]`: one record per unique mention and stage (`before` or `after`), containing a custody-only `mention_id`, `redacted_text`, and `assignments[]`. Each assignment includes the stable configured topic key, auditor-facing topic name and definition, one of ten volume cohorts `C01`–`C10` derived from the topic's native volume rank, and the final Boolean assignment. The two stages must be separate immutable snapshots/configuration digests even when they reuse a corpus.
- `study[]`: one record per unique mention with `axes_status`. `observed` records require native direction / target / use answers. `not_asked_outside_cut` records require all three axes to be `null`, `in_cut: false`, `lexical_filter_match: false`, and `base_voice_valid: true`; they are eligible only for the separate 30-case outside-cut sample. The blind packet asks the auditor the configured questions without exposing that status or substituting `none`. These cases never count toward the ≥200 observed axis cases. False `none`, false irony, and ambiguous-brand candidate flags must come from native sources, not inferred by the packager. Shortfalls remain explicit and source identities are never duplicated.
- To build motive strata, include key, display name, definition, layer truth and volume rank/cohort for the assigned motive. Layer truth must exist to be selected; rows without it remain census shortfalls and never get `unclear` placeholders. For nearest-four auditing, ranked `nearest_motives` and a unique assigned motive are required. The current native exporter stores the four saved candidate keys as an unordered set and keeps all positive membership answers as multi-label memberships; it does not infer ranking or select a winner, so this quota remains short until native rank/prediction provenance is available.

The native exporter uses exact source IDs, current native ownership/rights helpers, versioned saved study guidance, persisted axes and motive answers, exact membership-stage candidate keys as an unordered nearest-four set, source proofs, and measured Study ledger receipts. Motive volume cohorts come from the exact completed output summary. It fails closed or records explicit shortfalls when a source is unavailable; it does not select a latest execution, make substitute labels, infer candidate flags, or report a κ receipt without its native paired-pass evidence. Listening ledger lineage and paired-layer pass receipts are currently incomplete, so their missing totals stay explicit. It writes a private source manifest bound to the snapshot digest for custody verification.

## Sampling and audit boundaries

- Listening uses 500 distinct mentions in each stage, 50 per volume cohort. The whole package deduplicates source identities across both stages; when the two stage exports share the same mention IDs, the second stage can therefore report a shortfall. Shortfalls are explicit; records are never duplicated to reach quota.
- T&B has one disjoint set of at least 200 cases, each asking the auditor for direction, target, and use together. It emphasizes mixed (50), at least 40 in each target, ambiguous-brand candidates (30), and false-irony candidates (30). False `none` candidates are included at 30 inside and 30 outside the cut. Candidate membership and current answers stay in the separate private key; shortfalls are reported by opaque refs.
- Motive purity/layer evidence takes 10 distinct mentions for each of the 20 largest motives. Nearest-four assignment takes 20 distinct mentions per each of the ten motive-volume cohorts. All T&B selected source identities are disjoint from the Listening selections and from other T&B strata.
- Human-study comparison for the 22 causes is deliberately not part of the snapshot schema, selection, manifest, or key generator. It may be prepared only by a separate post-freeze process against the private human study, after the blind results are sealed.

The structure of study axes and methodology templates is based on the versioned query-engine study contract. These sample sizes define an audit census protocol, not classifier accuracy targets or release gates.
