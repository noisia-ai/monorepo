# R16 blind package tooling

The read-only native exporter binds explicitly supplied Listening generations and one completed Study execution to the exact workspace/actor. It writes only private `.data/piloto-masivo/r16/` files. The packager then creates blind auditor packets and a separately held custody key; neither tool edits labels, calls a provider, or runs either study. Use synthetic fixtures in tests. Do not run an export for a client corpus until the operator has approved it and the required native source evidence is available.

## Commands

```sh
pnpm exec tsx --tsconfig tsconfig.base.json --test scripts/r16/blind-package.test.ts scripts/r16/native-audit-export.test.ts scripts/r16/native-audit-export-receipts.test.ts scripts/r16/study-audit-custody.test.ts
NOISIA_R16_NATIVE_AUDIT_EXPORT_APPROVED=1 pnpm exec tsx --tsconfig tsconfig.base.json scripts/r16/native-audit-export.ts \
  --workspace <workspace-uuid> --actor <authorized-user-uuid> \
  --before-generation <exact-generation-uuid> --after-generation <exact-generation-uuid> \
  --study-execution <completed-execution-uuid> \
  --out .data/piloto-masivo/r16/native-snapshot.json
pnpm exec tsx --tsconfig tsconfig.base.json scripts/r16/blind-package.ts build \
  --snapshot .data/piloto-masivo/r16/native-snapshot.json \
  --seed .data/piloto-masivo/r16/custody-seed.txt \
  --out .data/piloto-masivo/r16/blind-package \
  --key .data/piloto-masivo/r16/custody/answer-key.json
pnpm exec tsx --tsconfig tsconfig.base.json scripts/r16/blind-package.ts verify --package .data/piloto-masivo/r16/blind-package
```

The exporter requires an explicit `NOISIA_R16_NATIVE_AUDIT_EXPORT_APPROVED=1` environment value and `DATABASE_URL`; it prints no identifiers, text, URLs, or secrets. The command is an operator action and must not be run against a client corpus before separate approval. The custody seed must be at least 32 bytes, have no group/other permissions, and be created and retained privately by the custodian. The snapshot must also have no group/other permissions. The packet directory and custody key must be separate, new paths under `.data/piloto-masivo/r16/`; the builder refuses existing output/key paths and symlinked paths. A per-output exclusive lock and atomic hard-link publication make concurrent writers fail closed if a key already exists; there is no check-then-overwrite path. It uses mode `0700` for directories and `0600` for files, builds in a temporary sibling directory, then publishes the packet directory by atomic rename. If a process dies, inspect a leftover `.lock` and confirm no builder is running before removing it. Back up the custody key separately from the auditor packet. Do not send the manifest or answer key until the auditor has frozen results; do not share the seed.

Packet filenames and row order are deterministic from the custody seed but opaque: they do not encode study, stage, cohort, label, or stratum. Each packet has an opaque `packet_ref`; the manifest maps that ref to a generic filename and aggregate census counts so each shortfall is identifiable to the auditor without exposing the stage or semantic stratum. Visible stratum and axis coverage arrays are separately shuffled from the private custody-manifest order; only the separate custody manifest maps refs back to semantic stratum names. Axis subcoverage refs point to the single combined three-axis packet, but do not reveal which subquota a row belongs to. The manifest records source snapshot digest, measured stage cost/timing receipts, axis coverage shortfalls, and packet file hashes. Native nearest-four cases use the exact saved four-candidate set as an unordered set. The auditor answers independently for each candidate; the custody key retains each source membership probability and Boolean, including multiple positives or none. No rank or unique winner is inferred. The two-pass κ value, status, denominator, coverage, and recode count are excluded from the auditor packet and retained in the custody key; committed A/B layer steps are replayed through the Study product validator and stability helper. If the exact pair, required recode, or output consistency cannot be established, κ stays unavailable and the incomplete state remains explicit. `SHA256SUMS` covers every packet and the manifest, excluding the separately held answer key. `verify` checks packet structure, manifest-to-packet digests and ref coverage, and all SHA256 entries. A build with any sample shortfall or missing κ evidence writes the census but exits with status 2; it cannot be presented as meeting the target sample/evidence requirements.

The manifest now separates artifact integrity from H6 census readiness. `verify` may return `valid: true` with `readiness: "not_ready"` for a well-formed, hash-valid package that has shortfalls or legacy evidence gaps. A selected-count/case-count mismatch is an integrity error. Readiness checks the fixed strata quotas (two stages × ten cohorts × 50; 20 motives × 10; ten nearest cohorts × 20; 200 observed axes; 30 outside-cut cases), axis subquota census, official motive rank receipt, measured native receipts, and all shortfalls. Legacy manifests without the readiness protocol remain integrity-verifiable but are reported not ready. Candidate flags remain candidate pools and no quality metric is confirmed before answers are separately sealed.

The motive stratum sequence is the exporter's canonical `summary.motives` order sorted by official mention count descending and stable motive-key tie-break. The rank is carried as `official_motive_census`; the sampler does not reconstruct official rank from available membership answers. Missing official ranks or membership evidence remain empty strata and shortfalls.

`study-audit-custody.ts` provides a private filesystem boundary for a future Human22 read. `sealStudyFreezeV1` binds supplied study/output digests, private result paths and hashes, and human-reference roles/paths under a separately supplied allowed root; it does not open or hash human files. `verifyStudyFreezeV1` validates the seal and verifies all private study-result hashes. `readBoundReferenceV1` completes that verification and syncs the seal before reading a bound human reference, then records the observed reference hash in an append-only private receipt. Its fixture tests use synthetic files only. This helper does not parse answers or make an auditor response a prerequisite for creating the blind package.

## Snapshot contract (`r16-blind-snapshot-v1`)

The native exporter writes one JSON object with:

- `exported_at`, and `source.export_contract: "r16-native-audit-export-v2"` plus `source.export_digest` (SHA-256 hex of the immutable `r16-native-audit-source-manifest-v2` export/artifact manifest). Version 2 normalizes native receipt timestamps to ISO strings before hashing and persistence. The blind snapshot, packet and custody-key contracts remain version 1; historical artifacts are not rewritten.
- `study_provenance.listening_before_digest` and `.listening_after_digest` (SHA-256 hex of each immutable configuration/map), `study_contract_version: "signal-study-v1"`, the exact nonempty `methodology_template_version` (at most 80 characters), and the exact `methodology_template_digest` (`sha256:` prefix plus hex). The template version comes from the saved external configuration; `r16-v1` is one possible value. These values bind the packet to the native versioned study contracts and keep before/after map provenance separate.
- `study_guidance`: exact subject context and option definitions for direction, target and use, plus the versioned layer diagnostics/questions/definitions. The auditor needs this context to code all three axes and the motive layer without seeing the model's answer.
- `layer_agreement`: nullable two-pass agreement receipt containing eligible count, each pass's observed count and artifact digest, paired denominator, coverage, observed/expected agreement, κ or `null`, estimation state/reason, action, and boundary-recode count. The validator checks counts, digests, coverage arithmetic, the κ formula, and status/value consistency against the native `signalStudyLayerStabilityV1` result. Numeric κ is valid only when both passes cover the full eligible census and the paired denominator equals it. Partial coverage requires `kappa: null` and `insufficient_data`, which makes package evidence incomplete. Full coverage with expected agreement `1` requires `kappa: null`, `not_estimable`, and reason `expected_agreement_one`; this is a complete observed receipt, not fabricated κ or a coverage shortfall. Missing and unmeasured receipts stay explicit. A fully measured κ below 0.8 is retained and reported without blocking the package. The receipt is retained with the custody key, never in the blind packet or public manifest.
- `receipts.cost_scope: "native_provider_ledgers"`, `status`, nullable `total_cost_usd`, `total_reserved_usd`, and `total_elapsed_ms`, `timing_scope`, plus a nonempty `receipts.stages[]` with unique actual stage names and nullable cost/reserved/time fields. Costs are sums of deduplicated native ledger call IDs; incomplete or unsettled calls keep the total `null`. Reserved exposure is `null` when source lineage is missing, otherwise it sums the exact open reservations. Timing is the observed wall span from earliest start to latest end; stage windows may overlap and are not summed. Programmatic exporter calls may pass `supplemental_stage_receipts` for CSV/import/runtime artifacts (absolute paths under `.data/piloto-masivo/r16/`, SHA-256 verified, at most 1 MiB each). Historical reused receipts are never included in current totals. The exporter records attachment references and hashes but does not reinterpret their metrics; the receipt total covers native provider ledgers only.
- `listening[]`: one record per unique mention and stage (`before` or `after`), containing a custody-only `mention_id`, `redacted_text`, and `assignments[]`. Each assignment includes the stable configured topic key, auditor-facing topic name and definition, one of ten volume cohorts `C01`–`C10` derived from the topic's native volume rank, and the final Boolean assignment. The two stages must be separate immutable snapshots/configuration digests even when they reuse a corpus.
- `study[]`: one record per unique mention with `axes_status`. `observed` records require native direction / target / use answers. `not_asked_outside_cut` records require all three axes to be `null`, `in_cut: false`, `lexical_filter_match: false`, and `base_voice_valid: true`; they are eligible only for the separate 30-case outside-cut sample. The blind packet asks the auditor the configured questions without exposing that status or substituting `none`. These cases never count toward the ≥200 observed axis cases. Candidate flags come only from observed native answers: `none`, figurative/ironic use, and branded targets define review pools; none establishes that the prediction was false or that a branded target was actually ambiguous. The outside-cut cases are a lexical-filter omission sample because direction/target/use were not asked there, not a false-`none` prediction sample. Shortfalls remain explicit and source identities are never duplicated.
- To build motive strata, include key, display name, definition, layer truth and volume rank/cohort for the assigned motive. Layer truth must exist to be selected; rows without it remain census shortfalls and never get `unclear` placeholders. For nearest-four auditing, the native unordered four-candidate set and all four observed JEV membership answers are required. The sampler uses candidate cohorts to create comparable quotas and asks an independent membership question for each candidate; it does not infer ranking or select a winner.

The native exporter uses exact source IDs, current native ownership/rights helpers, versioned saved Study guidance, persisted axes and motive answers, exact membership-stage candidate keys as an unordered nearest-four set, source proofs, and measured native ledger receipts. Motive volume cohorts come from the exact completed output summary. It fails closed or records explicit shortfalls when a source is unavailable; it does not select a latest execution, make substitute labels, infer candidate flags, or report κ unless the native stability-proof helper replays the saved output and binds both passes and any recode. Listening calls are deduplicated by ledger and call ID; current costs are reported only for settled receipts. Author redaction uses the native known-label roster (recorded source label takes precedence; legacy author label and linked aliases otherwise); it does not detect names from prose. The private manifest hashes those rosters and stores the source call lineage, timestamps and supplemental receipt references without copying source author labels. It writes a private source manifest bound to the snapshot digest for custody verification.

Private JSON persistence and canonical hashing use bounded chunks, avoiding one monolithic JSON string. Each sink write is at most 64 KiB of UTF-8, including the trailing newline. Collectors and the sampler still retain their source arrays in memory. The writer validates the admitted JSON types before creating output files, rejects executable/custom objects without invoking them, and publishes new private files atomically without overwriting an existing artifact.

For a native export that may exceed Node's single-string limit, pass the returned `snapshot` directly to `writeBlindPackageFromExportedSnapshotV1`, together with its `snapshotPath`, the private `seedPath`, `packageDir` and separate `custodyKeyPath`. This programmatic path captures and freezes the plain JSON snapshot before any asynchronous work, verifies its exact serialized bytes against the persisted private file as a stream, then uses that same snapshot for sampling. A mismatch publishes neither package nor key. It rejects mutable builtins such as Date; native exports already contain ISO timestamps. The CLI build path above retains its ordinary JSON file parser and is suitable for snapshots that fit that parser.

## Sampling and audit boundaries

- Listening uses 500 distinct mentions in each stage, 50 per volume cohort. The whole package deduplicates source identities across both stages; when the two stage exports share the same mention IDs, the second stage can therefore report a shortfall. Shortfalls are explicit; records are never duplicated to reach quota.
- T&B has one disjoint set of at least 200 observed cases, each asking the auditor for direction, target, and use together. It emphasizes mixed (50), at least 40 in each target, candidate branded targets (30), and candidate figurative/ironic uses (30), plus 30 observed `none` cases inside the cut. A separate 30-case outside-cut lexical-filter omission sample asks the configured questions without claiming a native direction prediction. Candidate membership and current answers stay in the separate private key; shortfalls are reported by opaque refs.
- Motive purity/layer evidence takes 10 distinct mentions for each of the 20 largest motives. Nearest-four assignment takes 20 distinct mentions per each of the ten motive-volume cohorts. All T&B selected source identities are disjoint from the Listening selections and from other T&B strata.
- Human-study comparison for the 22 causes is deliberately not part of the snapshot schema, selection, manifest, or key generator. It may be prepared only by a separate post-freeze process against the private human study, after the blind results are sealed.

The structure of study axes and methodology templates is based on the versioned query-engine study contract. These sample sizes define an audit census protocol, not classifier accuracy targets or release gates.
